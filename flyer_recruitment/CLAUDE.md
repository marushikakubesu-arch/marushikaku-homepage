# flyer_recruitment（利用者募集チラシ）

## 概要
就労継続支援B型事業所「まるしかくベース」の利用者募集用チラシ（A4縦・印刷配布用）。
見学・体験希望者やご家族、相談支援専門員に向けて、植物に囲まれた明るい事業所の雰囲気と、
育成→撮影→商品化→販売→梱包発送までの作業内容を直感的に伝えることを目的とする。

## 技術スタック
- HTML + CSS（単一ファイル index.html、外部フレームワーク不使用）
- QRコード生成: `qrcode` npm パッケージ v1.4.4 の browser 向けビルドをローカル同梱（vendor/qrcode.min.js、オフラインで動作・外部送信なし）
- アクセスマップ: 外部地図サービスは使わず、道路・ランドマークを手描き風に表現した簡易SVGマップを自作（index.html内に直接記述）
- 印刷対応: `@page { size: A4; }` ＋ `.page` を 210mm×297mm 固定で実装。ブラウザの印刷機能でPDF化・印刷する想定
- 画像: homepage側の実写真・ロゴ、およびユーザーから追加で受け取った実写真を使用（images/配下にコピーして同梱、homepageフォルダへの相互参照はしていない）

## 設計の意図
- 一般的な福祉施設チラシの堅い印象を避け、植物ショップ／クリエイティブワークスペースのような明るく親しみやすいデザインを意図（余白を多く確保）
- 配色はhomepage（homepage/css/style.css の`:root`変数）と完全に統一している：
  --accent #EF9D2E（homepageの--color-primary）／--accent-dark #C97A17（同--color-primary-dark）／
  --accent-tint #FCE6BD（同--color-accent-soft）／--paper #FFFAF3（同--color-bg）／
  --ink #4A3F35（同--color-text）／--ink-soft #7A6F63（同--color-text-light）／--border #F0DDB8（同--color-border）。
  homepageの配色を変更した場合はこちらも合わせて更新すること
- ロゴ画像（.mark）は丸型にトリミングして表示（border-radius:50%）
- ヘッダー右上の余白に、homepage（homepage/css/style.css内の背景SVG）と同じ「葉っぱ散らし」装飾を追加（2026-09-17、「ホームページみたいに葉っぱを散らして」との指示）。
  homepageのCSS背景画像（base64エンコードされたSVG）をデコードし、同じ葉の形状（oval「o」／ハート型「h」／丸型「r」）と配色（緑#6b8f57、淡緑#e3ecdb、アクセントの粒はオレンジ#EF9D2E）をそのまま流用。
  実装はpath要素をdefsに置き、`<use>`のx/y+`transform="rotate(角度 x y) scale(倍率)"`で同じ点を軸に回転させるhomepageと同じ手法（`<symbol>`+viewBoxではなく素のpathをuseする点に注意。symbolだと入れ子のviewport扱いになりx/y+transformの挙動が変わってしまう）。
  `.leaf-scatter`はposition:absoluteでヘッダー右側の余白に重ねているだけなので、ページの高さレイアウトには影響しない。
  さらに「全体的に散らして」との指示を受け、`.flow-title`／`.appeal-title`／`.access-title`の3つの見出し行にも同じ手法で小ぶりの葉っぱ装飾（`.title-leaf`）を追加し、ヘッダーとあわせて計4箇所に散らしている。各見出しは1行テキストで右側が余白になっているため、その空きスペースに`position:relative`にした見出し要素へ`position:absolute; top:-3.5mm; right:0`で重ねている。
  さらにユーザーが「株式会社SOL」名義の別チラシ（緑基調、左上・左下の角に葉の枝、アクセスマップは今回と類似構成）の写真を提示し「こんな感じで要所要所に散りばめて」と指示。これを受けてページの左上・左下の角にも枝状の葉っぱ装飾（`.corner-leaf.tl`/`.corner-leaf.bl`）を追加した。
  ロゴ画像（.mark、page左padding 14mmより右に配置）と重ならないよう、corner-leafはpageの左padding幅と同じ13mm幅・34mm高さの細い縦長領域に収め、ロゴの左側の余白だけに収まるようにしている。
  実装上のハマりどころ：`<use x y transform="rotate(角度 x y) scale(倍率)">`という書き方（homepage側のCSS背景SVGそのままの記法）は、SVGの変換適用順序の都合でx/y・回転の軸・scaleが素直に「その点を中心に拡大縮小・回転」という意味にならず、要素が意図せずviewBox外に飛び出して見えなくなることがある（実際にヘッダー以外の複数箇所でこれが原因で葉が非表示になった）。回避策として、`<use>`のx/y属性は使わず`transform="translate(X,Y) rotate(角度) scale(倍率)"`の順で書く（scaleが先に原点に対して適用され、続くrotateも原点付近で完結し、最後のtranslateで狙った位置(X,Y)に平行移動されるため直感的な配置になる）。今後この葉っぱ装飾を複製・追加する際は、必ずこの`translate → rotate → scale`の順の書き方を使うこと
  なお、実サイズ（13〜32mm幅程度）では枝がかなり細く見えるため、ブラウザの通常スクリーンショットでは目視で見落としやすい。確認する際はビューポート幅を150px程度まで狭くしてその部分だけを大きく表示するか、要素を一時的にposition:fixedで拡大して確認するとよい（このセッションで実際に見落として「表示されていない」と誤認しかけた）
- メインビジュアルは1枚の横長写真ではなく、写真4枚（事業所外観・事業所内販売スペース・商品撮影スペース・PC作業スペース、この順で左から）を横一列4列のグリッドで配置し、各写真の下にキャプション（figcaption）を添えている
- 「作業の流れ」は 育てる→撮る→PCで作業する→売る→届ける の順（当初は売る・届けるの後にPCで作業するを置いていたが、「撮るの後にもってきて」との指示で並び替え）
- 「作業の流れ」の売る・撮る・PCで作業するの3アイコンは、メインビジュアルとは別の写真をそれぞれ使用している（images/step-sell.jpg・step-photo.jpg・step-pc.jpg）。
  これらは当初メインビジュアルと共用していたが、都度「ヒーロー部分はさっきのまま」との指示があったため、メインビジュアル側は元の写真を別ファイル（hero-exterior.jpg／hero-studio.jpg／hero-pc.jpg）として保持し、作業の流れアイコン側だけ新しい写真に差し替える、という方針で統一している。今後さらに写真を差し替える依頼が来た場合もこの方針（ヒーローとアイコンは別ファイルで管理）を踏襲すること
- 写真が正方形（1280×1280）なのに対しメインビジュアルの1セル（.photo-frame）は横長のため、`background-size:cover`だと写真の大部分が切れてしまう。「写真全体が見えるように」という指示に合わせ`background-size:contain`を採用し、セル背景色（--accent-tint）を余白として見せることで、トリミングなしで全体を表示している。
  実装はCSS Gridの各セル（.photo-frame）に背景画像（background-image/background-position/background-size:contain）を敷く方式。`<img>`+`object-fit`ではなく背景画像方式にしているのは、CSS Gridの行高さが画像の縦横比の影響で意図通りに計算されない不具合が確認されたため（`.photo-frame`の高さを`45mm`のように絶対値で固定した上で背景画像方式にすることで回避）
- アクセスマップは、ユーザーが提示した既存チラシの手描き風マップ（道路・河川・ランドマーク・方位磁針・目的地への赤矢印）のデザインを踏襲しつつ、位置関係は実際の地図に基づいて作成：
  当初OpenStreetMap（Nominatim／Overpass API）の座標から「鈴鹿市立神戸小学校は事業所の北西・約900m」と算出したが、ユーザーが実際のGoogleマップ（事業所の実ピン「職場」入り）のスクリーンショットを提示し、実際は小学校が事業所のほぼ真南・ごく近距離であることが判明したため訂正。
  原因はOSM上に同名「市立神戸小学校」のノードが2つ存在したこと（片方は誤った位置900m北西、正しいのは事業所から約100m南西＝lat 34.8846077, lon 136.5795081）。半径400m程度の狭い範囲で再検索することで正しいノードを特定できた（広い範囲・キーワードのみの検索は誤ったヒットを拾うリスクがあるため、地物検索は可能な限り狭い半径で行い、複数ヒットした場合はユーザー提示の実地図と突き合わせる）。
  河川についても、当初は根拠のない位置に描いていたが、ユーザーから「川もしっかり確認して」と指摘を受け、Overpass APIで事業所から半径120m以内の実際の水路ジオメトリ（ノード座標列）を取得し直した。無名の小水路（waterway=stream、OSM上に川名なし）が事業所の西側・約35〜45mを北西から南東へ流れ、事業所より南でさらに南へ向きを変えて鈴鹿市立神戸小学校付近を通過していくという実際の形状に基づいて経路を描いている。
  最終的に採用した位置関係（事業所を基準）：ティア鈴鹿神戸＝ほぼ真西・近い／鈴鹿市立神戸小学校＝ほぼ真南（やや西寄り）・約100m／鈴鹿市駅＝南南東・徒歩4分（約230m）／鈴鹿市役所＝駅よりさらに南東／無名の小水路が事業所の西側を北西から南へ流れ、小学校方面へ続く／鈴鹿線（線路）がティア鈴鹿神戸～事業所～鈴鹿市駅～鈴鹿市役所方面を通る。
  今後、位置関係の裏付けにはOSM座標のみで判断せず、可能な限りユーザー提示の実地図（スクリーンショット等）を優先すること。また、OSMの地物検索は広範囲・名前だけの検索だと同名の別データ（位置が不正確なもの）を拾う場合があるため、狭い半径での再検索や実地図との突き合わせで裏取りすること。
  CTAバナーとフッターの間に専用セクション（.access）として配置し、見出しに「鈴鹿市駅から徒歩4分」を明記
- 「まるしかくベースが選ばれる理由」のチェック風リスト（.appeal-list）のアイコン（icon-leaf）は緑色（#6b8f57、葉っぱ装飾と同じ緑）で固定。全体の指し色はオレンジ（--accent）だが、この葉っぱアイコンだけは「緑にして」との指示で個別に色指定している（var(--accent)ではなくハードコードで#6b8f57を指定）
- QRコードは外部サービスに情報を送らず、ローカルのJSライブラリでオフライン生成
- 画像を今後差し替える場合は、`images/`内の同名ファイルを上書きするだけでよい構造にしている
